# Учебное приложение: перенос в React

Цель — перенести учебное приложение в React и TypeScript, сохранив интерфейс, тексты, аудио, учебную логику и существующие URL. Перенос выполняется по функциональным частям: каждая часть получает одного владельца DOM и состояния.

## Первый этап

- Входной HTML учебного приложения находится в `original/index2.html` в корне репозитория и обрабатывается Vite. Публичный адрес остаётся `/original/index2.html`.
- Главное меню выбора класса рендерит React. Его граница — `#mainRadialMenu[data-react-owned="true"]`; сохраняются четыре пункта, CSS-классы и идентификаторы, необходимые существующим стилям и проверкам.
- Компонент управляет раскрытием меню и его переводами. Классические скрипты не должны заменять содержимое или регистрировать обработчики внутри этой границы.
- Типизированный адаптер вызывает текущий глобальный `showScreen`. Он сохраняет действующую цепочку навигации и остановки аудио до переноса соответствующих модулей.
- Остальные экраны и классические скрипты пока остаются прежними. Это переходная архитектура, а не завершённый перенос всего приложения.
- Аудио, изображения, модели и ещё не перенесённые скрипты остаются в `public/original`. Их адреса не меняются.

Код первого этапа:

```text
original/index2.html                         # HTML-вход Vite, прежний URL
src/features/practice/
  main.tsx                                  # синхронное монтирование до DOMContentLoaded
  PracticeApp.tsx                            # подписки на язык и видимость экрана
  legacy/bridge.ts                          # временная граница с языком профиля
  legacy/navigation.ts                      # установка навигатора и очередь хуков
  navigation/screenNavigator.ts             # переходы между экранами и фазы хуков
  navigation/navigationContext.ts           # useNavigator, useActiveScreen
  components/MainGradeMenu.tsx               # разметка и действия меню
  hooks/useRadialMenu.ts                     # состояние и жизненный цикл анимации
```

Контейнер `#levelsScreen` пока принадлежит старой навигации, его содержимое — React. Остальные скрипты исключают `[data-react-owned]` из обработки анимации и доступности; переводчик уже исключает `[data-i18n-managed]`. Старые реализации `toggleMainMenu` удалены, включая побочный вызов из голосового упражнения.

## Второй этап: навигация

- `window.showScreen` теперь принадлежит типизированному навигатору `src/features/practice/navigation/screenNavigator.ts`. Он проверяет, что цель — существующий `.screen`, переключает активный экран, прокручивает страницу вверх и уведомляет React через `useSyncExternalStore`.
- Прежняя цепочка из 11 обёрток `window.showScreen = function () { … previous(id) … }` удалена. Классические скрипты регистрируют хуки:

  ```js
  (window.practiceNavigationHooks = window.practiceNavigationHooks || []).push({
    name: 'unique-name',
    leave({ from, to }) {},   // остановить звук, сессии, микрофон
    prepare({ from, to }) {}, // перенести разметку до показа экрана
    enter({ from, to }) {},   // инициализировать видимый экран
  });
  ```

  Скрипты, загруженные до модуля, кладут хуки в массив; `legacy/navigation.ts` при установке забирает их и заменяет массив очередью, которая регистрирует хуки напрямую. Порядок фаз: все `leave` → все `prepare` → переключение → все `enter`; внутри фазы — порядок регистрации.
- Повторное присваивание `window.showScreen` выбрасывает ошибку: обёртки больше не допускаются. Неизвестный экран вызывает ошибку до любых побочных эффектов. Сбой одного хука сообщается через `queueMicrotask`, но не прерывает переход. Если хук сам вызывает навигацию, остаток текущего перехода отменяется.
- Бывшая базовая функция из `script.js` стала хуком `legacy-shell` (остановка `<audio>`, очистка `#gameFeedback`, видимость шапки, `initAlippeLocal`).
- React получает навигатор через `NavigationContext`; `useActiveScreen()` заменил `MutationObserver` за классом `#levelsScreen`.

Зарегистрированные хуки: `legacy-shell`, `profile-language`, `app-audio`, `extra-learning`, `dauyspen-cards`, `dauys-shaqyru`, `g2-verb-module`, `alippe-focus-mode`, `learning-work`, `curriculum`, `grade-menu`.

## Третий этап: заголовок и мобильная навигация

- `PracticeHeader.tsx` управляет текстом и видимостью заголовка через язык профиля и активный экран. Заголовок показывается только на `levelsScreen`; старое изменение `style.display` в `legacy-shell` удалено. Неиспользуемый скрипт `scroll-header.js` удалён: на главном экране заголовок остаётся в потоке документа, на остальных скрыт.
- `MobileBottomNav.tsx` рендерит пять кнопок, переводы, активный пункт и `aria-current`. При переходе на главный экран выбирается «Басты / Главная», на другой учебный экран — «Прогресс». Открытие окна выбирает соответствующую кнопку; повторный переход на тот же экран сбрасывает этот выбор. Подписка снимается при размонтировании.
- Оба компонента используют порталы из единственного React-корня в `#practiceHeaderRoot` и `#practiceMobileNavRoot`. Контейнеры имеют `display: contents`, существующие CSS-классы сохранены. Границы отмечены `data-react-owned` и `data-i18n-managed`, поэтому старый переводчик не изменяет их текст.
- Разметка нижней панели, inline-обработчики, старый хук `mobile-bottom-nav` и подписка перевода удалены из HTML. Временный типизированный адаптер в `legacy/bridge.ts` открывает существующие окна профиля, рейтинга и ИИ и воспроизводит звук нажатия.
- Верхние элементы управления (тема, язык, аватар и монеты), содержимое модальных окон, прогресс и аудио пока остаются в legacy. Это завершённая часть переноса оболочки, не перенос всего приложения.

Проверки: `MobileBottomNav.test.tsx` проверяет вызовы всех действий, выбор пункта после переходов и очистку подписки. `e2e/practice-react.spec.ts` дополнительно проверяет реальное окно профиля, смену языка и возврат из учебного экрана на мобильном размере.

## Четвёртый этап: верхние элементы управления

- `TopControls.tsx` через портал в `#practiceTopControlsRoot` рендерит переключатель темы, кнопки языка, аватар и монеты. React владеет всем DOM этой панели; профиль открывается обычной кнопкой, доступной с клавиатуры.
- `usePracticeTheme.ts` восстанавливает тему из `localStorage`, обновляет фон и `body.theme-dark`, сохраняет выбор и синхронизирует оставшийся legacy-переключатель в окне профиля. Два старых набора обработчиков темы и копирование состояния при открытии профиля удалены. Подписка снимается при размонтировании.
- Кнопки языка вызывают существующий `setLangProfile`, а выбор получают через `profile-language-change`. Старый переводчик пропускает React-границу при обновлении классов языковых кнопок. Неиспользуемая заглушка `setLangProfile` удалена из `script.js`.
- Логика профиля публикует стабильный снимок `window.practiceProfileSummary` и событие `practice-profile-change` при загрузке монет, начислении награды, смене аватара и инициализации гостя. React читает снимок через `useSyncExternalStore`; прямые записи в `#coinCount` и `#topProfileImg` удалены. Таймер анимации монет перезапускается при новой награде и очищается при размонтировании.
- Авторизация, сохранение профиля и прогресса, загрузка фотографии и содержимое модальных окон пока остаются в legacy. Следующий этап — перенос профиля и прогресса с удалением временного адаптера снимков.

`TopControls.test.tsx` проверяет синхронизацию темы, действия панели, обновление снимков и очистку таймеров. Браузерные сценарии проверяют сохранение темы после перезагрузки, смену языка из обоих мест, открытие профиля клавиатурой и отображение наград.

## Пятый этап: рейтинг в разделе профиля и прогресса

- `LeaderboardModal.tsx` рендерит окно рейтинга через портал в `#practiceLeaderboardRoot`. Сохраняются CSS-классы, первые три медали, порядок по монетам, лимит 50 записей и возврат в профиль. Тексты загрузки, пустого списка, ошибки и кнопок принадлежат React и меняются вместе с языком.
- `profile/leaderboard.ts` содержит типизированную загрузку и нормализацию ответа. Используются прежний Supabase endpoint, публичный API-ключ из runtime-конфигурации и действующий токен пользователя, если он есть. Имена выводятся текстом, для аватаров разрешены только HTTP(S), при ошибке изображения остаётся первая буква имени.
- Каждый вызов открытия создаёт новую сессию окна. Закрытие, повторное открытие, переход на учебный экран и размонтирование отменяют запрос; поздний ответ игнорируется. Ошибку можно повторить кнопкой, смена языка не перезапускает запрос.
- `legacy/leaderboard.ts` сохраняет глобальные `openLeaderboardModal` и `closeLeaderboardModal` для существующего профиля и мобильных кнопок. Они вызывают React-контроллер, а не изменяют DOM. Старые разметка и `loadLeaderboard` удалены. При выходе с экрана хук `react-leaderboard` закрывает рейтинг без открытия профиля.
- Окно получает начальный фокус, удерживает Tab внутри и закрывается по Escape, фону или кнопке «Назад». Профиль, редактирование имени/фотографии и сохранение монет пока остаются в legacy.

Проверки перенесены со старого DOM-рендера в `LeaderboardModal.test.tsx`: небезопасные строки и URL, гостевой и авторизованный запросы, отмена и поздний ответ, повтор после ошибки, пустые/невалидные данные, клавиатура. `e2e/practice-leaderboard.spec.ts` проверяет вход из профиля и мобильной панели, переводы, ошибки и возврат; API в этих сценариях подменён тестовыми ответами.

## Шестой этап: профиль и сохранение монет

- `ProfileModal.tsx` владеет окном профиля: гостевым и авторизованным состояниями, именем, фотографией, монетами, языком, темой и настройками ИИ для администратора. Разметка профиля и более 400 строк прежней логики удалены из HTML и `script.js`. Окно закрывается по кнопке или Escape, удерживает клавиатурный фокус и возвращает его инициатору.
- `profile/profileApi.ts` читает существующую сессию из runtime-настройки ключа Supabase, проверяет срок действия и выполняет прежние REST-запросы профиля и `game_progress`. Ошибки HTTP обрабатываются явно; 401 удаляет только использованный токен, не затрагивая более новый. Имя и аватар обновляются после успешного сохранения. Пустое имя не отправляется; фотография должна быть изображением размером не более 2 МБ.
- `profile/profileStore.ts` — единый владелец профиля и монет для окна и верхней панели. Снимок `window.practiceProfileSummary`, событие `practice-profile-change`, переменные `coins`, `currentUserId`, `profileFullName` и прямые записи в DOM профиля удалены из классического скрипта. `legacy/profile.ts` оставляет совместимые глобальные функции `addCoins`, `getSupaAuth`, открытие/закрытие профиля и getters идентификатора и имени для упражнений и ИИ-помощника.
- Награды, начисленные во время первой загрузки, прибавляются к загруженному балансу. Записи монет выполняются последовательно; последующие награды попадают в следующий запрос. При ошибке значение остаётся в текущей сессии и доступен повтор сохранения. У гостя монеты не отправляются на сервер и не сохраняются после перезагрузки.
- Редактирование имени, чтение файла и сохранение аватара отменяются при закрытии окна или смене пользователя; поздние ответы игнорируются. Повторное открытие заново читает профиль. Ответ параллельной загрузки не перезаписывает завершённое редактирование. Общая загрузка баланса и очередь сохранения монет принадлежат приложению и продолжаются после закрытия окна; при смене аккаунта или размонтировании приложения отменяются.
- `ThemeSwitch.tsx` используется в верхней панели и профиле, а `usePracticeTheme` читает общее состояние. Адаптер, копировавший `checked` в legacy-поле, удалён. Настройки видимости ИИ хранятся в состоянии профиля; отдельный адаптер применяет их к ещё не перенесённым ИИ-виджетам.
- Одноразовое гостевое уведомление, сами ИИ-виджеты, аудио и учебные сессии пока остаются в legacy. Сохранение монет использует прежний API записи абсолютного баланса; серверный контракт не менялся.

Проверки: `profileStore.test.ts` покрывает награды во время загрузки, последовательные записи и повтор после ошибки, отмену редактирования, смену аккаунта, 401 и запоздалое обновление имени. `profileApi.test.ts` проверяет сессии, payload запросов и фотографии. `e2e/practice-profile.spec.ts` проверяет гостя, сохранение имени/аватара, ошибки, закрытие во время сохранения и настройки администратора. Серверные ответы в тестах подменены; реальные аккаунты не изменяются.

## Седьмой этап: общий аудиосервис

- `audio/runtime.ts` устанавливается вместе с React-приложением и владеет общей остановкой звука, TTS, предзагрузкой, озвучкой кнопок и звуковыми эффектами. `public/original/js/app-audio.js` и его подключение удалены; второй реестр и функции эффектов из `script.js` также удалены.
- `mediaCoordinator.ts` поддерживает один реестр активных записей. Новая учебная запись останавливает предыдущую, короткие эффекты могут звучать одновременно. После паузы, завершения или ошибки запись и её обработчики удаляются из реестра; повторный запуск регистрируется заново. Поздний результат старого `play()` не останавливает более новый запуск.
- `ttsClient.ts` сначала использует существующие казахские и русские аудиокарты, затем `/api/tts` с прежним выбором провайдера и запасным запросом. Кэш ограничен 50 записями. Остановка отменяет запрос и ожидание окончания; поздний ответ не начинает воспроизведение. `waitUntilEnd` возвращает успех только после `ended`, прерванная запись возвращает `cancelled`. Обработчики и blob URL освобождаются при остановке, замене записи и уничтожении сервиса.
- `preloader.ts` ограничивает загрузку своим origin, двумя параллельными запросами и прежним бюджетом фоновой предзагрузки: до 80 файлов не больше 180 КБ каждый. Сохраняются прогрев после первого жеста и приоритет коротких учебных записей. Таймеры, запросы и принадлежащий сервису AudioContext очищаются при уничтожении.
- Переходы, скрытие страницы и закрытие останавливают воспроизведение и вызывают адаптер остановки прежних микрофонных упражнений. `legacy/audio.ts` также сохраняет переход к артикуляционной карте и возврат назад. При HMR снимаются подписки и восстанавливаются заменённые глобальные функции, конструктор `Audio` и метод `play`.
- Глобальные `appTts`, `appAudioPreloader`, `trackAudio`, `_activeAudios` и функции остановки пока служат адаптерами для старых упражнений. Синтез Web Audio внутри упражнений, запись микрофона, распознавание речи и учебные состояния остаются в соответствующих legacy-модулях.

Проверки: модульные тесты покрывают отмену запросов и ожидания, кэш, ошибки и таймаут, повторный запуск, очистку обработчиков, лимиты предзагрузки и навигацию. `e2e/practice-audio.spec.ts` проверяет настоящее воспроизведение локальной записи, TTS с подменённым HTTP-ответом, кэш и поздний ответ после выхода. Сценарии учебных модулей дополнительно проверяют допуск к ответу после прослушивания, паузу, продолжение и остановку при выходе.

## Восьмой этап: сессии и экран слуховых упражнений

- `learning/session.ts` и `learning/content.ts` заменяют `learning-session.js`: типизированная сессия управляет порядком заданий, допуском к ответу после прослушивания, попытками, защитой от повторных нажатий и завершением цикла. `window.CorexLearning` временно сохраняется для ещё не перенесённых упражнений; второй реализации сессии больше нет.
- `ListeningPractice.tsx` владеет разметкой чисел, количества сигналов, высоты звука, темпа, ритма, вальса/марша и распознавания звуков для всех классов. Через портал компонент показывает упражнение в прежних `learningPracticeScreen`, `g0Task5` и `.recognition-screen`. Перемещение одного DOM-узла между экранами и старый рендер удалены из `learning-work-ui.js`.
- `learning/listeningStore.ts` хранит текущее задание, класс, ступень, варианты ответа и результат. Повторное прослушивание и смена языка сохраняют вопрос и расположение ответов. После смены языка или прерывания аудио требуется снова дослушать запись. Новая сессия, повторный старт, выход и смена аккаунта отменяют старое действие; поздние завершения и ошибки не изменяют новый экран.
- `learning/playback.ts` воспроизводит прежние локальные записи и синтезированные сигналы Web Audio. Завершение засчитывается после `ended` или окончания последовательности сигналов; ошибка, пауза и таймаут не открывают ответы. При выходе и скрытии страницы закрываются контексты, отменяются ожидания и очищаются обработчики и таймеры.
- `NumberDrawing.tsx` сохраняет рисование мышью/пальцем и очистку холста. Круговыми вариантами управляет общий React-хук `useRadialMenu`; старые скрипты доступности, переводов и анимации пропускают границу `data-react-owned`.
- `learning/progress.ts` сохраняет прежние ключи `eduCorex.learning.v1:<learner>` с разделением по классу, таблице и направлению. Распознавание сохраняет каждый правильный ответ, остальные режимы — завершённый цикл. Награда не дублируется при повторном ответе или переводе экрана; при недоступном хранилище итог остаётся на экране.
- Меню выбора учебной группы, контексты чтения по слогам, банк `grade-sounds.js`, отдельный движок `curriculum-session.js` и остальные учебные экраны пока остаются классическими скриптами. `legacy/learning.ts` связывает их с перенесёнными сессиями и общим сохранением прогресса.

Проверки: тесты сессии импортируют TypeScript напрямую. `listeningStore.test.ts`, `playback.test.ts` и `progress.test.ts` покрывают ошибки, отмену, поздние ответы, смену языка, результаты, ступени и награды. `e2e/practice-listening.spec.ts` проверяет React-границу и отсутствие старого скрипта, сохранение вопроса при переводе и изоляцию закрытого экрана. Существующие браузерные сценарии проверяют настоящее аудио, оба языка, классы 0–4 и рисование на разных размерах экрана.

## Девятый этап: каталог и уроки учебной программы

- `CurriculumPractice.tsx` и компоненты в `components/curriculum/` владеют содержимым `curriculumCatalog` и `curriculumPractice`: каталогом с категориями и страницами, выбором ответа, порядком картинок/предложений, отметками педагога, дыхательной пирамидой и подбором фонетических пар. Все 115 утверждённых уроков, их тексты и аудио остаются в прежнем банке `curriculum-content.js`.
- `curriculum/session.ts` заменяет `curriculum-session.js`. Движок сохраняет допуск к ответу после полного прослушивания, повторное использование уже прослушанного рассказа внутри сессии, попытки, помощь, ручную оценку и восстановление следующего неотвеченного шага. `curriculum-ui.js` и оба подключения старых скриптов удалены.
- `curriculum/store.ts` управляет уроком, стабильным порядком вариантов, каталогом, участием педагога и завершением цикла. Смена языка меняет интерфейс, сохраняя казахский учебный материал, вопрос, ответы и порядок картинок. Выход, новый урок, перезапуск и смена языка отменяют незавершённое воспроизведение; его поздний результат не открывает ответы. Смена ученика закрывает урок и перечитывает прогресс нового пользователя.
- `curriculum/playback.ts` поддерживает паузу и продолжение одной записи через общий аудиосервис. Прослушивание засчитывается только по `ended`. Вопросы и отдельные образцы фонетических пар не засчитываются как основной образец. Таймаут отслеживает остановившееся воспроизведение, не ограничивая длительность длинного рассказа; при паузе отсчёт приостанавливается. Обработчики и таймеры удаляются при завершении, ошибке, выходе, скрытии страницы и размонтировании.
- `curriculum/progress.ts` сохраняет прежние ключи `eduCorex.curriculum.v1:<learner>` и идентичность по классу, таблице, направлению, цели и уроку. Сохраняются последовательность фонетической пары, отдельная ручная оценка и отметка прежнего завершения. Перезапуск сразу сохраняет сброшенное прохождение; отказ хранилища не скрывает результат. Награда выдаётся один раз за завершённый цикл.
- Круговыми меню управляет React-хук `useRadialMenu`; старые переводчик, анимации и обработчики доступности пропускают React-границы. Вкладки поддерживают стрелки, Home и End; новый шаг получает фокус на заголовок. `legacy/curriculum.ts` сохраняет только входы `CorexCurriculumUI` для старых меню и проверок. Глобальный движок `CorexCurriculum` больше не нужен.
- Меню групп и классов (`grade-menu.js`), чтение по слогам, алфавит, банки учебных данных и остальные речевые упражнения пока остаются в legacy.

Проверки: `curriculumSession.test.ts` напрямую импортирует TypeScript-движок и проверяет целостность утверждённого банка и аудиофайлов. `curriculum/store.test.ts` и `curriculum/playback.test.ts` покрывают сохранение, восстановление, награды, разделение учеников, недоступное хранилище, паузу, таймаут и поздние события. `e2e/practice-curriculum.spec.ts` проверяет React-границы, стабильность вариантов при переводе, фокус и изоляцию закрытого урока. Существующие сценарии учебной программы, фонетических пар и круговых меню проверяют настоящее аудио, все 115 уроков и мобильные размеры.

## Десятый этап: меню классов и учебных групп

- `GradeMenus.tsx` через порталы рендерит десять меню: классы 0–1, 2, 3, 4, работу со звуком, голосом и дыханием, вложенное голосовое меню, предложения и «Слушай и учись». Разметка меню и inline-обработчики удалены из HTML; `grade-menu.js` и его подключение удалены полностью. Меню, навигация по страницам, выбор класса и кнопки возврата отмечены `data-react-owned` и `data-i18n-managed`.
- `menus/definitions.ts` хранит типизированные пункты, переводы и действия. Сохраняются прежние экраны, порядок, пять пунктов на странице и все 115 ссылок на утверждённые уроки. Названия уроков остаются на казахском; интерфейс переводится средствами React. `data-destination` заменяет зависимость браузерных проверок от текста inline JavaScript.
- `menus/gradeStore.ts` хранит текущий класс и последний выбор 0 или 1. Переход в старший класс не сбрасывает младший; выход из общего меню звуков возвращает в выбранный класс. Страница меню сохраняется отдельно для каждого класса при смене языка и возврате из урока. Вход в работу с голосом из главного меню, как прежде, сбрасывает страницу и сворачивает круг.
- `useRadialMenu` управляет анимацией и доступностью пунктов. Скрытые, свёрнутые и неактивные пункты исключены из клавиатурной навигации. Смена страницы или класса отменяет прежнюю анимацию, восстанавливает временные стили и не показывает скрытые варианты. Размеры областей нажатия в голосовых меню, включая вложенное legacy-меню, адаптированы к узким телефонам, чтобы кнопки не пересекались с центром.
- `legacy/grades.ts` оставляет адаптер `CorexGrades` для ещё не перенесённых упражнений и вызывает их существующие входы. `learning-work-ui.js` теперь обслуживает только чтение по слогам, получает класс из нового хранилища и сбрасывает недослушанный образец при его смене. Алфавит и его всплывающее слово остаются вне React-границ меню.

Проверки: `gradeStore.test.ts` проверяет сохранение младшего класса, возврат и подписки. `e2e/practice-grade-menus.spec.ts` проверяет десять React-меню, отсутствие inline-обработчиков, все 115 ссылок, страницы по классам, переводы, клавиатуру и смену класса во время анимации. Существующие браузерные сценарии проверяют переходы в слуховые, голосовые и пространственные упражнения и возврат на разных размерах экрана.

## Одиннадцатый этап: чтение и алфавит

- `ReadingPractice.tsx` владеет четырьмя экранами `g0TynysByTask`, `g0TynysByTask2`, `g0TynysByTask3`, `g0TynysByTask4`: разбиением на слоги, парами строчных/прописных слогов, пирамидой слова и пирамидой предложения. Сохранены адреса экранов, CSS-классы, предустановленные слова и прежнее правило слогоделения. Стили вынесены из HTML в `reading/reading.css`; inline-обработчики и четыре набора глобальных функций удалены.
- `reading/store.ts` управляет вводом, построением строк, последовательным прослушиванием и отметкой педагога. Запись прослушивания появляется только после окончания образца, отметка педагога сохраняется отдельно и однократно. Изменение ввода, класса, языка или пользователя отменяет старую попытку. Ввод сохраняется при возврате на экран в рамках текущей сессии пользователя; смена аккаунта очищает его. Возврат из слогов учитывает меню, из которого открыто упражнение.
- `reading/playback.ts` использует общий TTS и существующий управляемый проигрыватель записей. Предустановленные слоги воспроизводятся из локальных файлов без обращения к TTS. Выход, остановка, смена образца и открытие алфавита отменяют текущую последовательность, включая паузы между записями. Отменённый запрос или позднее событие аудио не засчитывается как прослушивание. Отмена алфавитной записи не запускает запасной файл.
- `reading/sentences.ts` сохраняет существующий `/api/ai-chat` для построения предложений из одного слова. Полное предложение разбирается локально. Запрос получает `AbortSignal` и ограничение ожидания; поздний ответ после редактирования или выхода игнорируется. Ошибку можно повторить. Ввод предложений сохраняет пробелы при наборе с клавиатуры.
- `AlphabetPanel.tsx` рендерит 42 казахские и 33 русские буквы, примеры слов, изображения положения рта и режим одной буквы. Алфавит монтируется только на активном экране. Кнопки доступны с клавиатуры; всплывающие слова удерживают фокус, закрываются по Escape и возвращают фокус. Выход очищает полноэкранный режим и останавливает звук.
- Дубли алфавита удалены из `script.js`, `i18n-profile.js`, `grade234-functions.js` и HTML. `learning-work-ui.js` и `CorexSyllableContext` удалены. `legacy/reading.ts` связывает состояние с навигацией, языком, классом и профилем; единственный алфавитный адаптер `playAlippeSoundLocal` пока нужен упражнению с поездом. Автоматическая озвучка кнопок пропускает новые аудиоэлементы, чтобы не прерывать образцы.

Проверки: модульные сценарии проверяют отмену и поздние результаты, последовательность аудио, смену пользователя, повтор после ошибки, разбор ответа ИИ и клавиатуру алфавита. `e2e/practice-reading.spec.ts` проверяет четыре экрана на двух языках, реальные локальные слоги, отметку педагога, генерацию и ошибки ИИ с тестовыми ответами, возврат, алфавит и узкий мобильный экран. Реальная генерация ИИ в этих тестах не проверяется.

## Правила следующего переноса

1. Выделить экран и перечислить его входы: параметры задания, язык, прогресс, аудио и переход назад.
2. Перенести учебное состояние в самостоятельный TypeScript-модуль. Общая слуховая сессия уже находится в `learning/session.ts`, сессия учебной программы — в `curriculum/session.ts`.
3. Перенести разметку и обработчики в React, сохранив визуальные CSS-контракты. Удалить старую реализацию и исключить этот DOM из legacy-обработчиков.
4. Очищать таймеры, подписки, воспроизведение и микрофон при выходе. Поздний результат асинхронной операции не должен изменять следующий экран.
5. Проверить сценарии и сборку, затем убрать ставшие ненужными глобальные адаптеры. Не дублировать учебную логику в двух реализациях.

Очередь следующих этапов: артикуляция и речевые модели → оставшиеся ИИ-виджеты и классические скрипты.

## Проверки

Новый файл `e2e/practice-react.spec.ts` проверяет React-границу, четыре пункта, смену языка, управление клавиатурой, переход в старый экран и обратно, повторную загрузку и ошибки страницы. Существующий `e2e/ui.spec.ts` проверяет адаптивность главного меню в двух языках и темах.

```sh
npm test
npm run build
npm run test:ui -- e2e/practice-react.spec.ts
npm run test:ui -- e2e/practice-grade-menus.spec.ts e2e/voice-navigation.spec.ts e2e/spatial-matrix.spec.ts
npm run test:ui -- e2e/practice-reading.spec.ts
npm run test:ui -- e2e/practice-profile.spec.ts e2e/practice-leaderboard.spec.ts
npm run test:ui -- e2e/practice-audio.spec.ts
npm run test:ui -- e2e/practice-listening.spec.ts e2e/learning-work.spec.ts e2e/grade-sounds.spec.ts e2e/dance-rhythm.spec.ts
npm run test:ui -- e2e/practice-curriculum.spec.ts e2e/curriculum.spec.ts e2e/phonetic-pairs.spec.ts e2e/exercise-orbits.spec.ts
npm run test:ui -- e2e/ui.spec.ts
```

Для проверки собранного приложения через production-сервер (PowerShell):

```powershell
npm run build
$env:UI_TEST_PRODUCTION = '1'
$env:UI_TEST_PORT = '8387'
npm run test:ui -- e2e/practice-react.spec.ts e2e/ui.spec.ts
Remove-Item Env:UI_TEST_PRODUCTION
Remove-Item Env:UI_TEST_PORT
```

В этом режиме Playwright запускает `server/production-server.mjs` и не переиспользует dev-сервер. `node tools/verify-production-learning-assets.mjs` отдельно проверяет совпадение статических ресурсов и наличие скомпилированного React-входа; исходный HTML больше не сравнивается с выходным побайтово.

Фикстура Playwright подменяет загрузчик фонемной модели для обычных UI-проверок; успешное прохождение этих тестов само по себе не подтверждает реальный инференс модели. Для перенесённых упражнений дополнительно проверяются завершение аудио перед ответом, повторная попытка, однократное начисление результата и остановка при выходе.
