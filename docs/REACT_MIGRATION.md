# Учебное приложение: перенос в React

Цель — перенести учебное приложение в React и TypeScript, сохранив интерфейс, тексты, аудио, учебную логику и существующие URL. Перенос выполняется по функциональным частям: каждая часть получает одного владельца DOM и состояния.

## Первый этап

- Входной HTML учебного приложения находится в `original/index2.html` в корне репозитория и обрабатывается Vite. Публичный адрес остаётся `/original/index2.html`.
- Главное меню выбора класса рендерит React. Его граница — `#mainRadialMenu[data-react-owned="true"]`; сохраняются четыре пункта, CSS-классы и идентификаторы, необходимые существующим стилям и проверкам.
- Компонент управляет раскрытием меню и его переводами. Классические скрипты не должны заменять содержимое или регистрировать обработчики внутри этой границы.
- Типизированный адаптер вызывает текущий глобальный `showScreen`. Он сохраняет действующую цепочку навигации и остановки аудио до переноса соответствующих модулей.
- Остальные экраны и классические скрипты пока остаются прежними. Это переходная архитектура, а не завершённый перенос всего приложения.
- Аудио, изображения, модели и ещё не перенесённые скрипты остаются в `public/original`. Их адреса не меняются.

Код первого этапа:

```text
original/index2.html                         # HTML-вход Vite, прежний URL
src/features/practice/
  main.tsx                                  # синхронное монтирование до DOMContentLoaded
  PracticeApp.tsx                            # подписки на язык и видимость экрана
  legacy/bridge.ts                          # временная граница с языком профиля
  legacy/navigation.ts                      # установка навигатора и очередь хуков
  navigation/screenNavigator.ts             # переходы между экранами и фазы хуков
  navigation/navigationContext.ts           # useNavigator, useActiveScreen
  components/MainGradeMenu.tsx               # разметка и действия меню
  hooks/useRadialMenu.ts                     # состояние и жизненный цикл анимации
```

Контейнер `#levelsScreen` пока принадлежит старой навигации, его содержимое — React. Остальные скрипты исключают `[data-react-owned]` из обработки анимации и доступности; переводчик уже исключает `[data-i18n-managed]`. Старые реализации `toggleMainMenu` удалены, включая побочный вызов из голосового упражнения.

## Второй этап: навигация

- `window.showScreen` теперь принадлежит типизированному навигатору `src/features/practice/navigation/screenNavigator.ts`. Он проверяет, что цель — существующий `.screen`, переключает активный экран, прокручивает страницу вверх и уведомляет React через `useSyncExternalStore`.
- Прежняя цепочка из 11 обёрток `window.showScreen = function () { … previous(id) … }` удалена. Классические скрипты регистрируют хуки:

  ```js
  (window.practiceNavigationHooks = window.practiceNavigationHooks || []).push({
    name: 'unique-name',
    leave({ from, to }) {},   // остановить звук, сессии, микрофон
    prepare({ from, to }) {}, // перенести разметку до показа экрана
    enter({ from, to }) {},   // инициализировать видимый экран
  });
  ```

  Скрипты, загруженные до модуля, кладут хуки в массив; `legacy/navigation.ts` при установке забирает их и заменяет массив очередью, которая регистрирует хуки напрямую. Порядок фаз: все `leave` → все `prepare` → переключение → все `enter`; внутри фазы — порядок регистрации.
- Повторное присваивание `window.showScreen` выбрасывает ошибку: обёртки больше не допускаются. Неизвестный экран вызывает ошибку до любых побочных эффектов. Сбой одного хука сообщается через `queueMicrotask`, но не прерывает переход. Если хук сам вызывает навигацию, остаток текущего перехода отменяется.
- Бывшая базовая функция из `script.js` стала хуком `legacy-shell` (остановка `<audio>`, очистка `#gameFeedback`, видимость шапки, `initAlippeLocal`).
- React получает навигатор через `NavigationContext`; `useActiveScreen()` заменил `MutationObserver` за классом `#levelsScreen`.

Зарегистрированные хуки: `legacy-shell`, `profile-language`, `app-audio`, `extra-learning`, `dauyspen-cards`, `dauys-shaqyru`, `g2-verb-module`, `mobile-bottom-nav`, `alippe-focus-mode`, `learning-work`, `curriculum`, `grade-menu`.

## Правила следующего переноса

1. Выделить экран и перечислить его входы: параметры задания, язык, прогресс, аудио и переход назад.
2. Перенести учебное состояние в самостоятельный TypeScript-модуль. В `learning-session.js` и `curriculum-session.js` уже есть независимые от DOM движки, пригодные для такого переноса.
3. Перенести разметку и обработчики в React, сохранив визуальные CSS-контракты. Удалить старую реализацию и исключить этот DOM из legacy-обработчиков.
4. Очищать таймеры, подписки, воспроизведение и микрофон при выходе. Поздний результат асинхронной операции не должен изменять следующий экран.
5. Проверить сценарии и сборку, затем убрать ставшие ненужными глобальные адаптеры. Не дублировать учебную логику в двух реализациях.

Очередь следующих этапов: общая оболочка (шапка, нижняя мобильная навигация) → профиль и прогресс → аудио → группы упражнений и алфавит → артикуляция и речевые модели → удаление оставшихся классических скриптов.

## Проверки

Новый файл `e2e/practice-react.spec.ts` проверяет React-границу, четыре пункта, смену языка, управление клавиатурой, переход в старый экран и обратно, повторную загрузку и ошибки страницы. Существующий `e2e/ui.spec.ts` проверяет адаптивность главного меню в двух языках и темах.

```sh
npm test
npm run build
npm run test:ui -- e2e/practice-react.spec.ts
npm run test:ui -- e2e/ui.spec.ts
```

Для проверки собранного приложения через production-сервер (PowerShell):

```powershell
npm run build
$env:UI_TEST_PRODUCTION = '1'
$env:UI_TEST_PORT = '8387'
npm run test:ui -- e2e/practice-react.spec.ts e2e/ui.spec.ts
Remove-Item Env:UI_TEST_PRODUCTION
Remove-Item Env:UI_TEST_PORT
```

В этом режиме Playwright запускает `server/production-server.mjs` и не переиспользует dev-сервер. `node tools/verify-production-learning-assets.mjs` отдельно проверяет совпадение статических ресурсов и наличие скомпилированного React-входа; исходный HTML больше не сравнивается с выходным побайтово.

Фикстура Playwright подменяет загрузчик фонемной модели для обычных UI-проверок; успешное прохождение этих тестов само по себе не подтверждает реальный инференс модели. Для перенесённых упражнений дополнительно проверяются завершение аудио перед ответом, повторная попытка, однократное начисление результата и остановка при выходе.
